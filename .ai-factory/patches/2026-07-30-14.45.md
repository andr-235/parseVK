# Producer envelope strict validation + CI fixes

**Date:** 2026-07-30 14:45
**Files:** validation.py, ci.yml, validate_contract_examples.py, test_pilot_contract.py
**Severity:** high

## Problem

Второе ревью выявило 6 проблем:
1. Producer envelope создавался через конструктор, а не `model_validate(strict=True)` — строки проходили как UUID, `True` как schema_version
2. `.github/workflows/ci.yml` выпал из change detection для contracts
3. `.github/scripts/` не проверялся ruff
4. Два теста использовали пустой `demands: ()` — могли давать ложный PASS
5. `classify_fixture` использовал `split("-")[0]`, а не строгий prefix match
6. `_resolve_contract_model` не обрабатывал `list`, `set`, `frozenset`

## Root Cause

1. Отсутствие `strict=True` на уровне envelope — конструктор Pydantic не strict по умолчанию
2. Change detection — при рефакторинге CI потерялась строчка с `ci.yml`
3. Ruff scope — исторически не включал `.github/scripts/`
4. Тесты писались с минимальным payload без учёта `min_length=1` для demands
5. Классификация фикстур использовала эвристику вместо точного prefix matching
6. `_resolve_contract_model` копировал логику только для `tuple`

## Solution

- `prepare_for_publish`:
  - Header (`message_type`, `schema_version`) валидируется через `EnvelopeHeader.model_validate(strict=True)` до catalog lookup
  - Envelope создаётся через `MessageEnvelope[PayloadT].model_validate(strict=True)` вместо конструктора
- `ci.yml`:
  - Добавлен `ci.yml` в grep-паттерн change detection для contracts
  - Добавлен `.github/scripts/` в команду ruff
- `validate_contract_examples.py`:
  - `classify_fixture` переписан на строгий `startswith` prefix match; `None` → failure
- `test_pilot_contract.py`:
  - Добавлен модульный `make_valid_producer_payload_dict` с непустыми demands
  - `test_camel_case_payload_rejected` использует непустой payload + matching correlation_id
  - `test_producer_one_rejected` использует helper с `include_thread_replies=1`
- `_resolve_contract_model`:
  - Добавлены `list, set, frozenset` к origin check

## Prevention

- Всегда использовать `model_validate(strict=True)` вместо конструктора для boundary-валидации
- Change detection должен включать сам CI-файл (иначе изменение CI может пропустить проверку CI)
- Ruff должен покрывать все Python-файлы в репозитории
- Отрицательные тесты должны менять ровно одно условие; остальной payload — валидный
- Классификация имён должна использовать строгий prefix match, а не эвристику
