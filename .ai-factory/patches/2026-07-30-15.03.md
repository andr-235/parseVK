# Dynamic generic mypy fix + strict metadata tests

**Date:** 2026-07-30 15:03
**Files:** validation.py, test_pilot_contract.py
**Severity:** high

## Problem

1. `MessageEnvelope[contract.payload_model]` использует runtime-выражение как type argument — mypy --strict выдаст ошибку
2. Отсутствовали regression-тесты на новую strict валидацию producer envelope metadata
3. `task_run_id or uid1` маскирует falsy-значения (пустая строка, False)
4. Дублировались `make_valid_producer_payload_dict` и `TestPilotProducer.make_payload_dict`

## Root Cause

1. Новый код в `prepare_for_publish` скопировал паттерн `MessageEnvelope[contract.payload_model]` из `parse_for_consume`, но без `type: ignore`
2. Strict envelope validation добавили, но тесты писали только на payload
3. `or`-идиома копировалась из существующего кода без критической оценки
4. Копипаста при добавлении второго helper

## Solution

- Добавлен `_make_envelope_type(payload_model)` с `cast()` и `type: ignore[valid-type]` — один локализованный ignore вместо дублирования
- Producer authorization check перемещён после envelope strict validation (как в consumer)
- Добавлен `TestProducerEnvelopeStrictMetadata` с 13 тестами: accept/reject для каждого metadata поля
- `make_valid_producer_payload_dict` и `TestPilotProducer.make_payload_dict` используют `is None` вместо `or`
- Удалён дублирующий `TestPilotProducer.make_payload_dict`

## Prevention

- Для динамических Generic всегда использовать helper с cast + type: ignore
- Новые boundary-валидации всегда покрывать regression-тестами
- `or` для default values использовать только когда falsy-значения невалидны
- Не дублировать helpers
